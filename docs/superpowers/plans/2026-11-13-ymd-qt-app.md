# Yandex Music Qt/Kirigami App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a standalone Qt 6/Kirigami desktop app (`ymd-qt`) that controls the existing `ymd` daemon over its local HTTP API.

**Architecture:** C++ `YmdClient` owns key reading, HTTP/JSON, polling, commands and search; `Tray` owns `KStatusNotifierItem`; QML/Kirigami renders a single window. The app is a thin client: no OAuth token, no Yandex API, no player.

**Tech Stack:** Qt 6.10, Qt Quick, Kirigami 6.24, KF6 StatusNotifierItem, CMake, Qt Test, Docker Ubuntu 26.04, dpkg-deb.

**Spec:** `docs/superpowers/specs/2026-11-13-ymd-qt-app-design.md`

## Global Constraints

- App id `io.github.pbolkhovitin.ymdqt`; binary/package `ymd-qt`; display name «Yandex Music»; version `0.2.0`.
- No OAuth token or Yandex API access in the app; only `X-YMD-Session` to `127.0.0.1:8765`.
- No `#rrggbb` in QML; colors only `Kirigami.Theme` / Controls palette.
- No animations (`Behavior`, `NumberAnimation`, marquee).
- `format.js` is a byte-for-byte copy of `plasmoid/contents/ui/format.js`; `cmp` test enforces it.
- Build via Docker; host has no Qt dev packages.
- Commit + push after each task; gitleaks before push.

## Review Focus

- Daemon absent or key missing: window shows a clear error and «Повторить», never a blank/crashed window.
- 401 after key rotation: exactly one key re-read and retry; then a visible error, no request loop.
- Search/queue click uses the correct payload (`play_track` gets the track object, `queue_play` gets `{index}`).
- Close button hides to tray; only tray «Выход» quits.
- App and plasmoid can run simultaneously without state conflicts.
