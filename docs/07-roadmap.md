## Ближайшие задачи

### 1. Тексты песен — ✅ (демон, CLI, Noctalia)

- `api::lyrics()`: подпись `trackId + timeStamp`, запрос `format=TEXT|LRC`,
  второй GET по `downloadUrl`.
- `GET /v1/lyrics?id=`, кэш текста, `ymd lyrics <id>`.
- Кнопка «Текст» в попапе, подсветка текущей строки по `positionMs`
  (без анимации).

Разведка: `notes/lyrics-findings.md`.

### 2. Докачка после обрыва — ✅

- `.part` + `Range: bytes=<скачано>-`, размер из `Content-Range`.
- Частичный файл привязан к треку, кодекy, качеству и отпечатку ключа
  расшифровки (`<id>.<codec>.<quality>.part` + `.json`); при несовпадении
  загрузка начинается заново.
- Проверено живьём: обрыв на 41 % → повторный запуск продолжил с 14 МиБ из
  31.3, файл скачался, играет из кэша.

### 3. Ynison

WebSocket-синхронизация между устройствами, опционально за флагом.
Не блокирует основной сценарий: без Ynison плеер полностью работает.

### 4. Клиент Noctalia — ✅

Плагин живёт в `noctalia/`, ставится симлинком (`scripts/install-noctalia.sh`).
Панель: вкладки «Сейчас / Обзор / Жанры / Любимое», главная с плейлистами и
альбомами, подборки по настроению/жанру/эпохе с радио, избранное, вход по
Device Flow и настройки. Виды и источники данных — `docs/design/noctalia.md`,
метрики — `notes/design-audit.md`, грабли UI — `notes/noctalia-ui-findings.md`.

Дальше по Noctalia:

- бар: хост режет текст по ширине капсулы (~22 символа) — артист теряется,
  нужен короткий формат или перенос в tooltip;
- ~~пауза и play в баре неразличимы~~ — сделано: глиф меняется
  (`player-play` / `player-pause` / `music-off`);
- состояния загрузки/ошибки в баре — без retry-действия.

### 5. Отдельное приложение Qt/Kirigami — ✅

`ymd-qt` использует тот же демон `ymd` по HTTP и не дублирует API Яндекса.
Реализованы окно Kirigami, поиск, очередь, транспорт, режимы, трей и
`.deb` для amd64/arm64. Детали — `docs/11-qt-app.md`.

Ограничение: меню трея на Wayland может не открываться при DBus-вызове
`ContextMenu` без input serial; клик по иконке (toggle) и средняя кнопка
(play/pause) работают.

### 6. Логирование и зацикливание трека — ✅

Демон пишет в journald и в `~/.local/state/ymd/ymd.log` (ротация 5 МиБ),
хвост читается `ymd logs [-n N] [-f]`. События `eos -> next`, `queue step`,
`stream resolved` содержат `track`, поэтому расхождение «состояние ≠ звук»
видно сразу.

По этим логам найдена причина зацикливания при `repeat=one`: `command_async`
резолвил URL следующего трека, а `advance` оставлял текущий индекс. Теперь
оба используют общий `plan_step()`, выбранный индекс передаётся в команду.
Детали — `notes/logging-findings.md`.

## Порядок

```text
KDE-порт ✅ ──> Qt-приложение ✅ ──> открытие и аккаунт ──> тексты ──> докачка ──> Ynison
```

Тексты и докачка не зависят друг от друга; Qt-приложение использует
стабильный HTTP-контракт, который уже зафиксирован.

Открытие музыки и аккаунт: API демона готов — `/v1/home`, `/v1/discovery/*`,
`/v1/radio`, `/v1/favorites`, `/v1/config`, `/v1/auth/*` (`docs/12-discovery-account.md`).
Плазмоид и Noctalia-панель переведены на `like_track`, лайк больше не теряется.
`ymd-qt` получил «Обзор»: главная, каталог жанров/настроений, страница тега,
радио и избранное. Дальше — те же разделы в попапе Plasma и экран Device Flow
в `ymd-qt`.
