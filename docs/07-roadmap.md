# 07. План разработки

Оценки — в «человеко-днях» одного разработчика, без учёта ревью и API-сюрпризов.

## Фактический статус (2026-11-13)

| Этап | План | Факт |
|---|---|---|
| P0 | 1–2 дня | ✅ S1–S8; S9 не понадобился — вход через Device Flow / импорт токена |
| M1 | 5–7 дней | ✅ поиск, поток, `ymd search/track/album/artist/stream` |
| M2 | 7–10 дней | ✅ GStreamer-плеер, исходящий MPRIS, панель, очередь, обложки |

Отклонения от плана и причины — в `notes/m1-findings.md` … `notes/m4-findings.md`.

## P0 — спайки (1–2 дня) ⛔ блокирует всё

Цель: убрать неизвестность до написания кода. Каждый пункт — воспроизводимая
проверка, а не «кажется, работает».

| # | Проверка | Как | Критерий приёмки |
|---|---|---|---|
| S1 | Версия `plugin_api` установленного Noctalia | `noctalia --version` / лог при enable плагина-пустышки | известен максимум (ожидается 43) |
| S2 | Полный набор `barWidget.*` | enable `hello`-плагина, `noctalia.log` всех методов | список методов + сигнатуры записаны в `docs/03` |
| S3 | `ui.*` внутри бар-виджета | отрисовать `ui.row`/`ui.progress` в виджете | рендерится, без ошибок в логе |
| S4 | `noctalia.httpStream` → SSE | поднять `python3 -m http.server` с `text/event-stream` | строки приходят по одной, разрыв детектируется |
| S5 | `noctalia.readFile` вне своего каталога | прочитать `$XDG_RUNTIME_DIR`-файл | чтение разрешено |
| S6 | MPRIS виден шеллу | `playerctl` + заглушка `dbus`-плеера | встроенный виджет `media` показывает трек |
| S7 | GStreamer `playbin3` → PipeWire на хосте | `gst-launch-1.0 playbin3 uri=…` | звук идёт, `pactl` видит поток |
| S8 | niri event stream | `niri msg --json event-stream` | приходят `WorkspaceActivated`/`WindowFocusChanged` |
| S9 | Свой OAuth `response_type=code` + loopback | зарегистрировать приложение в Яндекс ID | редирект на `127.0.0.1` работает |

Итог P0: заметка `notes/p0-findings.md` с фактическими сигнатурами API и
решением «идём/меняем подход».

## M1 — «играет из бара» (5–7 дней) ✅

- `ymd serve`: httpd + SSE + `session.key` + `doctor`.
- `auth`: `import` токена (быстрый путь), затем полный OAuth по итогам S9.
- `api`: `/account/about`, `/tracks/{id}/full-info`, `/search`.
- `player`: GStreamer, `play/pause/next/prev/seek`, очередь в памяти.
- `mpris`: `MediaPlayer2.Player` полностью.
- Плагин: `widget.luau` (`onClick`, `onRightClick`, `onScroll`), `bridge.luau` (SSE).
- systemd unit + `ymd doctor`.

**DoD:** в баре отображается трек; клик ставит паузу; `playerctl` и медиа-клавиши
работают; после `systemctl --user restart ymd` виджет восстанавливается сам.

## M2 — панель и библиотека (7–10 дней) ✅

- `panel.luau`: поиск (`submitOnEnter`), результаты, альбом, артист, плейлисты.
- Очередь: просмотр, `shuffle`/`repeat`, удаление, переход к треку.
- Лайк/дизлайк из бара (СКМ) и панели.
- Клавиатурная навигация, `onKey`.
- Кэш обложек (`/v1/cover`), `cover_in_panel`.

**DoD:** сценарий «нашёл альбом → включил → лайкнул → переставил очередь» целиком
без терминала; `ymd doctor` зелёный.

## M3 — волна, тексты, офлайн (10–14 дней) — частично: волна ✅, офлайн ✅, тексты ⏳

- Rotor: `/rotor/session/new`, `/tracks`, `/feedback`; индикатор волны в баре.
- Тексты: подпись `HMAC`, `ui.label` в скролле.
- Офлайн: `encraw`-загрузка, AES-CTR, SQLite, LRU, «только офлайн».
- Главная (`landing3`, `blocks`), история.
- Шорткат control-center, launcher `>ym`.
- Адаптивность `auto`: правила `env` → `mode`.

**DoD:** в самолёте играет скачанный плейлист; волна переключает треки без панели;
текст открывается офлайн.

## M4 — полировка и поставка (5–7 дней)

- Ynison (опционально, за флагом), deeplink `yandexmusic://`.
- Уведомления о смене трека, OSD через `noctalia.osd`.
- Упаковка: `ymd.spec` (Fedora/COPR), `cargo install`-инструкция, `plugin.toml` +
  `catalog.toml`, `thumbnail.webp`, README, `ru/en` переводы.
- `[[plugin.release]]` для хостов с `plugin_api` ниже текущего.
- Документация пользователя: установка, настройки, `troubleshooting`.

**DoD:** установка с нуля на чистом хосте по README занимает < 10 минут; плагин
включается из локального `path`-источника; `doctor` объясняет каждую ошибку.

## Порядок и зависимости

~~~text
P0 ──> M1 ──> M2 ──> M3 ──> M4
        │      │
        │      └─ требует M1 (state/SSE)
        └─ требует S9 (или импорт токена как временный путь)
~~~

## Что можно распараллелить

| Поток | Задачи |
|---|---|
| A. Демон | api, player, mpris, cache |
| B. Плагин | widget, bridge, panel, настройки |
| C. Инфраструктура | systemd, spec, doctor, CI |

A и B стыкуются на `/v1/state` и `/v1/cmd` — контракт фиксируется до старта
(`02-architecture.md`), поэтому потоки независимы.

## Риски по срокам

Самый вероятный сдвиг — `S9` (свой OAuth-клиент) и `S2/S3` (недокументированные
части `barWidget`/`ui` в баре). Оба закрываются в P0, до основной разработки.
