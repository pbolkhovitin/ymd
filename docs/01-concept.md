# 01. Концепция

## Проблема

Официальный клиент Яндекс Музыки — тяжёлое Electron-приложение с собственным
окном и анимациями. Для рабочего стола нужен клиент, который живёт в панели:
минимум площади, мгновенный отклик, нативный звук и управление с медиа-клавиш.
Поддерживаются две среды: **KDE Plasma 6** (плазмоид) и **niri + Noctalia**
(бар-виджет и панель). Демон и контракт у них общие.

При этом музыка — не фоновый значок: нужны поиск, очередь, «Моя волна», лайки и
офлайн. Поэтому две поверхности: **компактный виджет в панели** и **панель/
попап по требованию**.

## Видение

> Яндекс Музыка как часть панели: одна строка состояния, цвета темы,
> ноль анимаций — и полный доступ к поиску, очереди и волне в попапе.

## Цели

1. **Паритет функций** с официальным клиентом в разумных пределах:
   вход, поиск, очередь, волна, лайки, офлайн, качество звука.
2. **Нативность среды**: PipeWire через GStreamer, MPRIS для медиа-клавиш,
   systemd --user; цвета — `Kirigami.Theme` в Plasma и `noctalia.getColor`
   в Noctalia.
3. **Минимализм**: ноль анимаций по умолчанию, никаких захардкоженных цветов.
4. **Устойчивость**: вся работа с непубличным API — в демоне; клиенты не знают
   эндпоинтов и не видят токен.

## Не-цели

- Не воспроизводим Electron-клиент и его анимации.
- Не поддерживаем среды без панельного API: нужен Plasma 6 или Noctalia 5.
- Не делаем второй Spotify: только Яндекс Музыка.
- Не храним токен в клиентах.
- Не гонимся за пиксель-в-пиксель копией официального клиента.

## Принципы

| # | Принцип | Следствие |
|---|---|---|
| P1 | **Панель — не окно** | В панели только трек и 2–3 действия; остальное — в попапе |
| P2 | **Ноль движения** | Нет переходов, marquee, пульсаций; прогресс обновляется шагом |
| P3 | **Цвета темы** | `Kirigami.Theme`/`PlasmaComponents3` в QML, `noctalia.getColor` в Luau; hex запрещён |
| P4 | **Мгновенность** | Состояние в демоне; клиент — проекция, сеть только через демон |
| P5 | **Одна правда** | Плеер и очередь живут в `ymd`; UI не создаёт второе состояние |
| P6 | **Деградация, не отказ** | Нет демона → видимая ошибка и кнопка «Повторить»; нет сети → кэш |
| P7 | **Одна структура** | Общие блоки идут в одном порядке во всех клиентах (`docs/design/ui-rules.md`) |

## Поверхности

| Поверхность | Роль | Где |
|---|---|---|
| Компактный виджет Plasma | трек, play/pause, переход в попап | панель Plasma |
| Попап Plasma | обложка, seek, громкость, транспорт, поиск, очередь, режимы, волна | `plasmoid/contents/ui/FullRepresentation.qml` |
| Бар-виджет Noctalia | иконка и «трек — артист», клики и колесо | `noctalia/widget.luau` |
| Панель Noctalia | обложка, прогресс, транспорт, поиск, очередь, режимы | `noctalia/panel.luau` |
| Окно `ymd-qt` | то же, что попап, плюс плейлисты и кэш | `app/qml/Main.qml` |
| MPRIS | медиа-клавиши, виджет `media`, блокировка | `org.mpris.MediaPlayer2.ymd` |
| CLI | отладка, скрипты, авторизация, кэш | `ymd` |

## Сценарии

**Работа.** Панель сверху, открыт терминал. В панели — «Трек — Артист». Клик
открывает попап; медиа-клавиша ставит паузу.

**Поиск.** Открыть попап, ввести запрос, Enter, клик по результату — трек играет,
очередь обновляется.

**Волна.** Кнопка «Волна» заменяет очередь партией радио; демон сам догружает
следующие треки.

**Офлайн.** Скачанный трек играет из кэша; в поиске у него стоит `✓`.

**Нет демона.** Плазмоид показывает «Ключ не найден. Запущен ли ymd?» и кнопку
«Повторить»; после `systemctl --user start ymd` всё восстанавливается.

## Метрики успеха

| Метрика | Цель |
|---|---|
| Память демона | < 80 МБ RSS в простое |
| Задержка «клик → звук» | < 300 мс для кэша, < 1.5 с для сети |
| Задержка UI | обновление состояния 1 с при игре, 3 с в паузе |
| Анимации | 0 по умолчанию |
| Правки при изменении API | только в демоне |

## Ограничения и этика

- API непубличный: возможны блокировки и изменение схем.
- Офлайн-кэш расшифровывает `encraw` (транспортное шифрование, не DRM);
  правовая сторона — на пользователе.
- Плазмоид исполняется в процессе plasmashell, поэтому в нём нет секретов и
  прямой работы с API.
