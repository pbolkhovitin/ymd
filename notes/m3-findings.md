# M3 — офлайн-кэш: факты и ловушки

## Что работает (проверено 2026-11-12)

| Шаг | Результат |
|---|---|
| `GET /get-file-info` с `transports=encraw` | 200, `transport=encraw`, есть `key` (hex, 32 символа) |
| размер файла | `Range: bytes=0-0` → `Content-Range: bytes 0-0/<total>` |
| докачка чанками по 1 МиБ | 200/206, каждый чанк расшифровывается своим offset |
| расшифровка | AES-128-CTR, counter = `offset/16` (16-байтовый BE), skip = `offset%16` |
| результат на диске | `64072310.m4a`, 4 616 689 байт, сигнатура `ftyp` (mp4) |
| воспроизведение | `player: load file:///home/pbolk/.local/share/ymd/media/64072310.m4a` |
| индекс | `~/.local/share/ymd/media/index.json` |

Команды:

```bash
ymd download 64072310 --quality nq    # ~4.4 МиБ
ymd cache list                        # 64072310  4.4 МиБ  nq  Кино — MACAN
ymd cache path 64072310               # путь к файлу
ymd cache remove 64072310
ymd cache info                        # каталог, индекс, суммарный размер
```

## Ловушки

1. **`/tracks/{id}` отдаёт `{"track": {...}}`**, а не массив. В `download` нужно
   брать `value["track"]`, иначе `track_from_value` падает с «нет id».
2. **`artists` в API — массив объектов** (`{"name": "MACAN"}`), а из UI приходят
   строки. Парсер поддерживает оба варианта.
3. **Без `Content-Range` нельзя считать прогресс** — если сервер не отдал размер,
   загрузка отклоняется, а не пишет файл наугад.
4. **Расшифровка до записи**: если писать чанк как есть, файл будет мусором;
   `sniff()` (ftyp/fLaC/0xFFFB) — дешёвая проверка, что ключ и offset верные.
5. Кэш приоритетнее сети: `resolve_url` сначала смотрит `cache::path_for`, поэтому
   скачанный трек играет без токена и без запросов к API.

## Лимит кэша и LRU (проверено)

Конфиг: `~/.config/ymd/config.toml`

```toml
[cache]
limit_mb = 2048   # по умолчанию 2048
```

Лимит проверяется после каждой загрузки: записи удаляются по возрастанию `at`
(самые старые первыми), только что скачанный трек не трогается.

Прогон с `limit_mb = 20`: было 35.4 МиБ в 8 треках → стало **19.8 МиБ в 5 треках**,
старые файлы удалены вместе с записями индекса.

## Скачивание альбома (проверено)

```
ymd download-album 3448499 --quality nq
альбом: «Angry Birds в кино» — 7 треков
[1..7/7] ok … → итого: готово 7, ошибок 0, занято 35.4 МиБ
```

Уже скачанные треки пропускаются (`[N/M] уже скачан`), ошибки по отдельному
треку не прерывают альбом.

## Отметка «скачано» в поиске (проверено)

`/v1/search` отдаёт `cached: true|false` (`cache::is_cached`). Панель рисует `✓`
перед названием. Проверка: трек `145486974` → `cached True`, остальные `False`.

## Докачка после обрыва (проверено 2026-11-14)

| Шаг | Результат |
|---|---|
| `timeout 4 ymd download 31190260 --quality lossless` | оборвано на 41 %, `.part` = 13 631 488 Б |
| повторный `ymd download 31190260 --quality lossless` | лог `resuming download from=13631488`, прогресс начался с 44 %, итог 32 823 293 Б |
| `ymd cache list` | `31190260  31.3 МиБ  lossless` |
| play через `/v1/cmd play_track` | `player: load file:///…/31190260.flac`, позиция растёт |
| порча `key_sha` в `.part.json` | загрузка началась с нуля (защита сработала) |

Устройство: имя `<id>.<codec>.<quality>.part`, рядом `.json` с `key_sha`
(SHA-256 ключа расшифровки) и `total`. Возобновление только при совпадении
всех трёх (кодек/качество — в имени, ключ и размер — в мете). AES-CTR
расшифровывает с любого смещения (`counter = offset/16`), поэтому обрыв
посреди чанка не ломает файл.

Грабли: первый тест на `nq`-треке (3.4 МиБ) успел скачаться за 2 секунды —
`.part` не осталось; для проверки нужен lossless-трек ≥15 МиБ.
