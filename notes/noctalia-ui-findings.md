# Noctalia UI: факты и грабли (2026-11-14)

Проверено живьём на Noctalia 5.4.1, niri, eDP-1 1920×1080, демон `ymd` 0.2.0.

## Форма данных discovery

- `/v1/discovery/metatags` → `{groups: [{id, title, tags: [{tag, title, children}]}]}`.
  Группы: `moods` «Настроения» 17 (2 с детьми), `activities` «Занятия» 11,
  `genres` «Жанры» 24 (18 с детьми), `epochs` «Эпохи» 9. Поля `trees`/`leaves`
  не существует — первая версия панели из-за этого показывала только жанры.
- `tag` — **отображаемая строка**, а не id: `/v1/discovery/tag?tag=mood:calm`
  отвечает 502 (`Metatag mood:calm not found`), а
  `?tag=Осенняя%20музыка` — 200 `{tag, title, station: "mood:autumn", playlists}`.
  Жанры наоборот: `/genres` даёт `id`, станция строится как `genre:<id>`.
- `/v1/discovery/tag` не всегда даёт `station`: у «Душевное» `station = null`,
  у «Осенняя музыка» — `mood:autumn`. Кнопка «Радио по подборке» показывается
  только при непустой станции.
- `/v1/home` — `blocks[].items[]` с `kind`: `playlist` (`uid`, `playlistKind`),
  `album` (`id`), чарт — плоские треки без `kind`.
- `/v1/album?id=` — volumes сплющены в один список треков; добавлен из-за
  карточки альбома на главной.

## Yoga/`ui.*`, из-за чего панель ломалась

1. **`ui.scroll` — только последний ребёнок корневого `ui.column`.** В Yoga нет
   `flexShrink` (в бинаре есть `flexGrow`, `minHeight`), поэтому скролл с
   контентом выдавливал вкладки и шапку за пределы панели. Порядок, который
   работает: header → track/progress → transport → nav → hint → scroll.
2. `height = 420` на корне не заменяет `flexGrow` и только добавляет артефакты.
3. `contentAlign = "start"` выравнивает текст кнопки по левому краю;
   `textAlign` принимается, но не работает.
4. Хот-релоад применяет изменения неатомарно: после правки структуры панель
   может отрисоваться с «раздутыми» контролами (кнопки-квадраты, съехавшая
   шапка). Лечится полным перезапуском: `pkill -x noctalia; nohup noctalia -d &`.
   `noctalia msg plugins update` файлы не перечитывает.

## Луа

- `local function`, объявленная ниже места вызова, не видна: получается
  глобал `nil` → «attempt to call a nil value» и панель отключается «после
  повторных таймаутов». Взаимные ссылки — только через forward-локалы.
- `repeat` — ключевое слово: поле JSON читается как `queue["repeat"]`.

## Проверки без мыши

Клик мышью и клавиатуру инжектировать нечем, панель фокуса не берёт. Поэтому
в `panel.luau` есть IPC-события для отладки:

```bash
noctalia msg plugin 'pbolkhovitin/yandex-music:panel' all view genres
noctalia msg plugin 'pbolkhovitin/yandex-music:panel' all tag 'Осенняя музыка'
noctalia msg plugin 'pbolkhovitin/yandex-music:panel' all refresh
```

Скриншоты: `grim -o eDP-1`, кроп 620×720+690+20, ×1.4. Панель открывается на
мониторе с фокусом — перед `panel-open` нужен `niri msg action focus-monitor eDP-1`.

## Что осталось непроверенным

- `tag_group` (вложенные теги) — только код, мышью не открыть.
- Ввод в `ui.input`: у панели нет клавиатурного фокуса, поиск в панели
  практически недоступен; закрывается из настроек/обзора.
- Поведение колеса и правого клика на строках списка.

## Воспроизведение из списков и размер транспорта

- `queue_set` без `play = true` только подменяет очередь: `st.track` остаётся
  прежним. Отдельный `cmd("play")` после этого новый трек не запускает —
  ветка `play` резолвит URL только при `status != "playing"`, а он ещё
  `playing` от прошлого трека. Правильно — один вызов:
  `POST /v1/cmd {"op":"queue_set","payload":{"tracks":[…],"index":0,"play":true}}`.
  Проверено: `{ok:true, rev:45}`, `status: playing`, позиция 2 → 1999 мс за 2 с.
- Внешне «кнопки разного размера» — не размеры: таргет у всех 30×30, но
  glow/pause при глифе 16 px выглядел мельче ghost-стрелок, а hover заливал
  весь квадрат, из-за чего одна кнопка казалась крупнее. Сейчас таргет
  32×32, глиф 18, play/pause 20 (пауза) и 22 (воспроизведение).

## «ymd off» после рестарта демона и висячий симлинк (2026-11-14)

Симптом: виджет в баре показывает «ymd off», но клик запускает трек, ПКМ
открывает рабочую панель, значок в баре не обновляется.

Причины — две, сложились:

1. **Симлинк плагина вёл в никуда.** `~/.local/share/noctalia/plugins/yandex-music`
   указывал на `/home/pbolk/github/ym-noctalia/noctalia`, а каталог после
   переименования стал `~/github/ymd`. Noctalia держала старый экземпляр в
   памяти (отсюда рабочие клики и открытие панели), но `plugins list` плагин
   уже не видел, а file-watcher следил за несуществующим путём — хот-релоад
   не срабатывал. Лечение: `bash scripts/install-noctalia.sh` (создаёт
   симлинк на текущий корень) + `noctalia msg plugins enable`.
2. **`rev` не монотонен между жизнями демона.** Виджет отбрасывал состояния
   с `rev <= s.rev`, а после `systemctl --user restart ymd` счётчик начинается
   заново. Один таймаут в момент рестарта → `s.status = "off"`; дальше все
   успешные опросы отбрасывались, виджет залипал в «ymd off» навсегда.

Исправление в `noctalia/widget.luau`:

- пропускать только точное совпадение `rev` (`if rev == s.rev then return end`);
  понижение `rev` трактуется как рестарт демона;
- ошибка показывается как «off» только после трёх подряд неудач и сбрасывает
  `s.rev = -1`, чтобы первое же успешное состояние применилось;
- переходы статуса пишутся в лог: `[ym] playing -> paused` (диагностика).

Проверка: рестарт сервиса при `rev 26` → демон поднялся с `rev 1`; в логе
`[ym] playing -> paused`, виджет принял новое состояние, «off» не залип.

Профилактика: `ymd doctor` теперь проверяет симлинк плагина
(`noctalia plugin ok -> /home/pbolk/github/ymd/noctalia` или
`симлинк висит — переустановите`).

## Глиф бара по состоянию (2026-11-14)

Пользователь выбрал динамический вариант, семантика действия:
`player-pause` — играет (клик поставит паузу), `player-play` — пауза,
`music-off` — демон недоступен/пусто.
Имена проверены по `/usr/share/noctalia/assets/fonts/tabler.json` (5958 иконок,
все три есть; `music` тоже валиден).

Реализация: `ICONS[status]`, `s.icon_status` вместо `s.icon_set` — вызов
`barWidget.setGlyph` только при смене глифа, чтобы не мигал при reload.
`onEnable()` сбрасывает `icon_status`, чтобы после перезапуска плагина глиф
восстановился.

Проверено: hot reload `widget.luau` → `[ym] off -> playing`, ошибок Luau нет.

## Обложка в панели: порядок `update()` (2026-11-14)

`update()` вызывает `ensure_cover()` **до** `refresh()`, поэтому на первом тике
`s.cover_url` ещё пуст и обложка не запрашивалась — до следующего обновления
(2 с) или до смены трека уже с открытой панелью.

Исправление: `ensure_cover()` вызывается в `apply()` сразу после
`s.cover_url = state.track.cover`, то есть на том же кадре, где пришло новое
состояние. Побочно это чинит случай, когда тик `update()` не приходит (панель
только что открылась): обложка грузится из `refresh()`.

Проверено: `cover_63330704.img`, `cover_73583263.img`, `cover_64072310.img`
появляются в `pluginDataDir()` через ~1 с после смены трека; в логе нет
`download failed`.
