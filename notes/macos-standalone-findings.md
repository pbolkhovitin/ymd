# Самостоятельный macOS bundle — 2026-11-14

## Окружение и границы проверки

Хост: macOS 27.2.1 (26B131), arm64. Цель сборки: macOS 13 Ventura+
на Apple Silicon. На самом Ventura приложение пока не запускалось.
`LSMinimumSystemVersion=13.0`, deployment target Rust/Swift — 13.0.
Упаковщик проверяет ARM64 Mach-O всех вложенных библиотек и самого клиента,
завершаясь ошибкой при минимальной версии ОС выше 13.0.

Пользователь подтвердил ручной запуск: «я сам запустил все ок».
Повторный вход в действующий аккаунт, Developer ID и notarization не
проверялись. Новые HTTP account/device/wave методы проверены локальными
fixture; токен и ключ сессии в отчёт не копировались.

## Выбор runtime

Первый эксперимент с Homebrew дал 35 МБ `.app` / 15 МБ DMG, но dylib
содержали minimum macOS 27.0/27.2. Такой runtime не подходил под Ventura.
Использована официальная универсальная сборка GStreamer 1.28.8:

```text
gstreamer-1.0-1.28.8-universal.pkg
SHA-256: d371ab04a7632713626836c2fc234e863cc98484c74c473eba99b0fbd9b3a3fe
```

Проверка `otool -arch arm64 -l` её `libgstreamer` показала minimum 11.0.
`macos/prepare-runtime.py` распаковывает `.pkg` в кэш проекта через
`pkgutil --expand-full`, не запускает установщик и package scripts и не
изменяет `/Library/Frameworks`. Совпадающие файлы/симлинки пересекающихся
payload объединяются; несовпадающие дают ошибку.

Rust использует готовые FFI-объявления, поэтому вместо devel-пакета со
статическими библиотеками достаточно метаданных линковки четырёх `.pc`:
GStreamer 1.28.8 и GLib/GObject/GIO 2.82.4. Сборка использует только этот
`PKG_CONFIG_LIBDIR`, отдельный `target/macos13/` и rpath приватного SDK.

В приложение включаются только ARM64-срезы выбранных аудиоплагинов и
транзитивных dylib: 64 Mach-O runtime плюс SwiftUI-клиент. GTK, Python,
инструменты сборки, полный SDK и Homebrew в DMG не входят. AAC декодирует
`avdec_aac` официального libav, FLAC и MP3 — соответствующие аудиоплагины.

## Проверки переносимости, звука и TLS

В `macos/Tests/check-runtime.py` создаётся копия `.app` в каталоге с
пробелами. Тестовый C-бинарник связывается с уже вложенными библиотеками;
недостающие dylib не восполняются из среды сборщика. Для процесса действуют
запреты чтения `/opt/homebrew` и `/usr/local` и PATH только из системных
каталогов. Приложение пользователя при этом не останавливается.

Подтверждено:

```text
ok: аудиоэлементы найдены, звук завершён с EOS
ok: аудиоэлементы найдены, HTTPS завершён с EOS
ok: недоверенный TLS-сертификат отклонён
```

HTTPS проверялся через `souphttpsrc` с CA из bundle, отрицательная проверка
— с единственным посторонним CA. Callback `accept-certificate` фиксирует
отказ и возвращает FALSE. Проверка сертификатов не отключается.

Два важных отличия от Homebrew:

- Официальный runtime использует GIO OpenSSL, а не GnuTLS.
- `ssl-ca-file` в libsoup3 игнорируется. В macOS-ветке плеера CA передаётся
  через `gio::TlsFileDatabase` в `tls-database` при `source-setup`.

SIP очищает DYLD-переменные у системных программ: проверочная команда
сначала запускает sandbox-exec, затем env, который задаёт окружение
целевому бинарнику. В приложении Foundation Process задаёт его ребёнку
напрямую. Это окружение не меняет окружение других приложений.

## Запуск и выход

Перед холодным запуском старый ymd был остановлен; запущенного клиента
на тот момент не было. Открытие `.app` запустило `Contents/Helpers/ymd`;
путь процесса и PPID подтвердили, что родитель — `ymd-menubar`.
`/v1/health` вернул `ok:true`, версию 0.2.1. Штатный Quit приложения
освободил порт 8765 и завершил собственный демон.

Переносимые Swift-проверки используют реальные временные процессы и
локальный HTTP. Проверены:

- собственный start/stop и отсутствие дубликатов;
- сохранение внешнего процесса;
- конфликт, падение при запуске/в работе, таймаут и retry;
- короткие запросы готовности, HTTP session/account/device и `wave_start`;
- изоляция окружения и допустимые HTTPS-адреса OAuth;
- ожидание выхода после отложенного TERM и ограниченный SIGKILL только
  собственному процессу, который игнорирует TERM;
- отбрасывание поздних state/account-ответов после stop, reconnect и crash;
- исчезновение внешнего демона с доступным переподключением;
- сохранение владения живым собственным процессом при ошибке HTTP.

Полный XCTest недоступен в установленном CLT (также отсутствует Testing).
Выполнен `bash macos/Tests/run-standalone-checks.sh`, компилирующий те же
компоненты через swiftc; XCTest suite сохранён для полного Xcode.

## Результаты финальной сборки

`LC_ALL=C YMD_APP_OUTPUT=.../dist/validation/ymd-menubar.app bash macos/build.sh`
завершился успешно. Отдельный output использован, чтобы не перезаписывать
приложение, уже запущенное пользователем.

```text
Runtime: 64 файлов Mach-O; все зависимости внутри .app; macOS 13.0+
готово: dist/validation/ymd-menubar.app
готово: dist/ymd-menubar-0.2.1.dmg (23M)
```

Приложение занимает около 54 МБ. Включена ad-hoc подпись всех вложенных
Mach-O с последующей подписью `.app`; Developer ID/notarization не проверены.
При Developer ID демон получает entitlement для приватного DYLD-пути,
необходимого для загрузки libsoup по имени.

Проверки кода: 44 теста Rust с официальным SDK и runtime прошли;
8 Python-тестов упаковщика прошли; Swift runner вывел 9 групп `ok`.
Ревью runtime и Swift закрыто после исправлений; версия проекта не менялась.

Финальные `hdiutil verify` и `codesign --verify --deep --strict` завершились
успешно. `scripts/docs-check.sh` выдал `ok`; `git diff --check` и синтаксис
Bash прошли. Gitleaks проверил историю и отдельный снимок всех изменённых
и новых файлов (включая неотслеживаемые) — утечек не обнаружено.
Пользователь разрешил коммит и публикацию macOS-релиза в форке `4epenaxa/ymd`,
с сохранением версии приложения 0.2.1.
