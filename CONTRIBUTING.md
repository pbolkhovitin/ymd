# Участие в разработке

Репозиторий публичный, ветка `main` защищена: пуш напрямую закрыт, нужен PR
с зелёными проверками `client-scope` и `commit-identity`.

## Подпись коммитов

GitHub привязывает коммит к аккаунту **по email автора**. Если в клоне стоит
чужой адрес, коммиты навсегда останутся за чужим аккаунтом.

```bash
git config --local user.name  "Имя Фамилия"
git config --local user.email "<ID>+<логин>@users.noreply.github.com"
git log -1 --format='%an <%ae>'          # проверить
```

`<ID>` — Settings → Emails → *Keep my email addresses private*; в профиле
показан готовый адрес вида `12345+login@users.noreply.github.com`.

Адрес также можно взять обычный, если он добавлен в аккаунт GitHub. Главное —
свой, а не коллеги.

CI проверяет авторов в PR (`.github/workflows/commit-identity.yml`): коммит с
чужим email роняет проверку. Список разрешённых адресов ведётся в самом
workflow; новый участник добавляет свой туда же вместе с первой правкой
(или просит владельца репозитория). Историю задним числом не переписываем.

> **История переписана 2026-11-14** (`git filter-repo`): из неё удалены копия
> OpenAPI-спецификации и первая версия иконки. Если ваш клон старше этой даты,
> переклонируйте репозиторий — старые и новые хеши несовместимы.

## Происхождение кода

Публичный репозиторий — значит, каждая строка должна иметь чистое
происхождение.

- Код и ассеты — только свои или под лицензией, совместимой с MIT.
- **Нельзя** присылать код, ресурсы, шрифты и тексты из официального клиента,
  из распакованных `app.asar`/декомпилированных бандлов и из чужих
  репозиториев без совместимой лицензии.
- Факты об API (пути, поля, форматы) копировать можно; чужую документацию —
  нет, только собственное изложение.
- Логотипы и товарные знаки правообладателя не добавляем: имя продукта —
  `ymd`, бренд допустим только в описательных строках. Подробнее — `LEGAL.md`.

Коммиты подписываем `git commit -s` (Developer Certificate of Origin): строка
`Signed-off-by: Имя <email>` подтверждает право передать код под MIT.

## Ветки и PR

- Ветка от свежего `main`: `feat/<тема>`, `fix/<тема>`, `docs/<тема>`.
- **Один PR — один клиент.** Правки `noctalia/` и `plasmoid|app/` в одном PR
  отклоняет `.github/workflows/client-scope.yml`. Изменения демона и общих
  доков — отдельным PR.
- В `main` попадает **один коммит на PR**: включён squash-merge, ветка
  удаляется после мержа.
- Перед PR: `bash scripts/docs-check.sh` (сверяет доки с кодом, маршруты `/v1/*`,
  копии `format.js` и версии манифестов); для плагина —
  `noctalia plugins lint ./noctalia`; для демона — `cargo test`.
- Упаковка: `gh workflow run ci.yml --ref <ветка> -f packages=true` собирает
  `.rpm` без выпуска тега (job `rpm (Fedora, вручную)`).
- `CHANGELOG.md` пополняется в том же PR: пункт в `[Unreleased]`. Версии
  в манифестах не правятся руками — только `bash scripts/version.sh --bump`.
- Ревью: `CODEOWNERS` запрашивает владельца каталога автоматически
  (`.github/CODEOWNERS`). Без Pro-плана это запрос, а не блокировка — мержить
  без ревью владельца не принято.

## Что и где менять

| Каталог | Кто ведёт |
|---|---|
| `noctalia/` | Noctalia-плагин |
| `plasmoid/`, `app/` | KDE Plasma 6 и `ymd-qt` |
| `daemon/` | общий, ревью обоих |
| `docs/design/` | общие правила UI, ревью обоих |

Демон — единственный владелец токена и API Яндекса; клиенты ходят только в
`127.0.0.1:8765`. Контракт `/v1` — `docs/02-architecture.md`.

## Настройки репозитория

Включено: squash-only мерж, удаление ветки после мержа, обновление ветки
из `main`, четыре workflow (CI, release, client-scope, commit-identity).
Ветка `main` защищена: обязательны проверки `scope` и `author`, нужно
одобрение ревью, force-push и удаление ветки запрещены. Администратор
(`enforce_admins = false`) может пушить напрямую — так выпускаются релизы.

## Релиз

Релиз делает мейнтейнер, порядок — `docs/13-versioning.md`:

```bash
bash scripts/version.sh --bump patch     # версия + раздел в CHANGELOG
git commit -am "chore(release): 0.2.1" && git push origin main
bash scripts/version.sh --tag            # v0.2.1
git push origin v0.2.1                   # запускает release.yml
```

Тег и версия в манифестах обязаны совпадать — workflow `release` падает
раньше сборки, если это не так. Пакеты и заметки появляются на странице
Releases автоматически.
