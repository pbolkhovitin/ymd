# Безопасность

## Что защищаем

- **OAuth-токен** хранится только в keyring (GNOME Keyring / KWallet) или в
  `~/.local/state/ymd/token` (0600) при недоступном keyring. В логи и ответы
  API он не попадает.
- **Capability-ключ** демона — `$XDG_RUNTIME_DIR/ymd/session.key` (0600,
  каталог 0700). Без него `/v1/*` отвечает 401; открыт только `/v1/health`.
- Демон слушает `127.0.0.1:8765`, наружу не выходит.

## Сообщить об уязвимости

Не открывайте публичный issue для уязвимостей. Используйте GitHub → Security →
*Report a vulnerability* (private advisory) либо письмо мейнтейнеру из профиля.

В отчёте: версия (`ymd --version`), как воспроизвести, что происходит.
Ответ — в течение недели.

## Что не является уязвимостью

- Обратно выведенные ключи подписи и публичные `client_id`/`client_secret`
  Android-приложения в коде: это не наши секреты, они публично известны и
  используются для совместимости с API.
- Доступ к `/v1/*` локального пользователя, который уже прочитал
  `session.key`: ключ защищает от других пользователей машины, не от владельца.
- Данные в `~/.local/share/ymd/media`: локальный кэш расшифрованных файлов.
